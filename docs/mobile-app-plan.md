## ধাপ ০: ব্যাকএন্ড প্রস্তুতি

অ্যাপ বানানোর আগে ছয়টা কাজ শেষ করতে হবে, নাহলে রোগী অংশ চলবে না অথবা প্রাইভেসি ঝুঁকি থাকবে। বর্তমান ওয়েবসাইটের কোন কাজই ভাঙা যাবে না, শুধু নতুন route যোগ হবে।

- [x] **সীমিত পাবলিক API:** নতুন endpoint শুধু নাম, স্ট্যাটাস, পরীক্ষার তারিখ, দেশ, পাসপোর্ট, token ফেরত দেবে। HIV/VDRL সহ টেস্টের ফলাফল, ফি ও ছবি থাকবে না। বর্তমান `public/check-report` পুরো মেডিকেল রেকর্ড পাঠায়, ওয়েবের জন্য তা আপাতত অপরিবর্তিত থাকবে।
- [x] **Token / Slip ID সার্চ:** সীমিত API পাসপোর্ট দিয়ে খোঁজে, Token (`pax_id`, যেমন BEST000752) ঐচ্ছিক দ্বিতীয় যাচাই হিসেবে দেওয়া যায়। শুধু Token দিয়ে সার্চ ডিফল্টে বন্ধ, কারণ Token ক্রমিক (BEST000001, 000002...), তাই যে কেউ সংখ্যা বাড়িয়ে সবার নাম ও পাসপোর্ট নম্বর পেয়ে যেত। `.env`-এ `PUBLIC_TOKEN_ONLY_SEARCH=true` দিলে চালু হবে।
- [x] **সার্ভারে PDF সার্টিফিকেট:** `barryvdh/laravel-dompdf` যোগ হয়েছে, লেআউট `resources/views/pdf/medical-certificate.blade.php`। সীমাবদ্ধতা: dompdf বাংলা যুক্তাক্ষর ঠিকভাবে জোড়া লাগাতে পারে না, তাই ছাপা রিপোর্টের নিচের বাংলা লাইনটির জায়গায় ইংরেজি বাক্য আছে; বাংলা নাম/ঠিকানা হেডার ও ফুটার ছবির ভেতরে থাকায় ঠিকই আসে। Fit/Unfit/Held up মিলিয়ে ইউনিফাইড স্ট্যাটাসের নিয়ম (`resources/js/lib/report-status.ts`) আগে শুধু ফ্রন্টএন্ডে ছিল, এখন PHP-তেও (`app/Support/ReportStatus.php`) একই নিয়ম আছে যাতে প্রিন্ট আর PDF একই ফলাফল দেয়। দুই জায়গার নিয়ম বদলাতে হলে একসঙ্গে বদলাতে হবে।
- [x] **Callback রিকোয়েস্ট:** নতুন টেবিল (নাম, মোবাইল, কারণ, স্ট্যাটাস), পাবলিক POST endpoint, আর স্টাফের জন্য লিস্ট বা Overview-এ সংখ্যা।
- [x] **Rate limit ও নিরাপত্তা:** লগইনে মিনিটে ৫ বার (প্রতি অ্যাকাউন্ট + IP), রিপোর্ট সার্চে মিনিটে ২০ বার, PDF ডাউনলোডে মিনিটে ১০ বার, Callback ফর্মে মিনিটে ৩ ও ঘণ্টায় ১০ বার সীমা। JWT মেয়াদ এখন ১ ঘণ্টা, refresh ১৪ দিন, অ্যাপ সেই refresh ব্যবহার করবে।
- [x] **Postman collection ও API ডকুমেন্ট:** `docs/postman/best-diagnostic-mobile.postman_collection.json` ও `docs/mobile-api.md`।
- [x] **Forgot password (বাড়তি, পরে যোগ হয়েছে):** স্টাফ username/email দিলে Brevo API দিয়ে ইমেইলে ৬ সংখ্যার কোড যায় (`POST /auth/forgot-password`), কোড দিয়ে পাসওয়ার্ড রিসেট (`POST /auth/reset-password`)। Brevo API key ডাটাবেসে এনক্রিপ্ট করা থাকে (`app/Models/AppSetting.php`), `.env`-এ না। রিসেট করলে পুরনো সব token বাতিল হয়ে যায়।
- [x] **Email ও IT Helpdesk সেটিংস (বাড়তি):** ওয়েব অ্যাডমিনের Site Settings পেজে নতুন কার্ড — Brevo API key/sender ও IT Helpdesk ফোন/ইমেইল বসানোর জায়গা (`GET/PUT /api/app-settings`, শুধু Admin)। IT Helpdesk তথ্য পাবলিক `site-settings` API দিয়ে অ্যাপে আসে।
- [x] **লোগো ব্যাকএন্ড থেকে (বাড়তি):** অ্যাপের সব স্ক্রিনের লোগো এখন `site-settings`-এর `logo_path` থেকে আসে (`best_mobile_app/src/components/ui/logo.tsx`), ইন্টারনেট না থাকলে বা লোড ব্যর্থ হলে অ্যাপের ভেতরের কপি ফলব্যাক হিসেবে দেখায়।

অবস্থা: **সম্পন্ন।** কোড ও টেস্ট সব পাস — ব্যাকএন্ড ৪৩টা (`tests/Feature/MobileApiTest.php`, `tests/Feature/PasswordResetTest.php`), মোবাইল অ্যাপ ৪৭টা। PDF আসল ডাটায় (patient BEST000038, BEST000710) রেন্ডার করে চোখে দেখে নেওয়া হয়েছে। বাকি শুধু **VPS-এ ডেপ্লয়** (`docs/mobile-api.md`-এর শেষ অংশে কমান্ড আছে) — local-এ যা করা সম্ভব তার সবটুকু হয়ে গেছে।

## ধাপ ২ ও ৩: স্টাফের বাকি কাজ

ধাপ ১ Play Store-এ টেস্টিংয়ে যাওয়ার পর এই দুটো ধাপ আপডেট হিসেবে যাবে, যাতে পরীক্ষার ১৪ দিন নষ্ট না হয়।

**ধাপ ২ (২-৩ সপ্তাহ):** নতুন রোগী ঢোকানো ও রিপোর্ট তৈরি — **সম্পন্ন, আসল ডাটা দিয়ে যাচাই করা হয়েছে**

| স্ক্রিন | কাজ | অবস্থা |
| --- | --- | --- |
| Entry | ৪ ধাপের wizard (ব্যক্তিগত, ভ্রমণ/এজেন্সি, ছবি, বিল), country/agency/MR সার্চেবল picker, ক্যামেরা/গ্যালারি ছবি, due amount লাইভ হিসাব | ✅ নতুন রোগী (BEST000711) তৈরি করে যাচাই করা হয়েছে |
| Reports (hub) | Report Entry, X-Ray Upload, Check Medical/Certificate — তিনটা কার্ডের লিস্ট | ✅ |

ছোট দুটো সরলীকরণ, সময় বাঁচাতে ইচ্ছাকৃতভাবে করা হয়েছে:
- তারিখের ফিল্ডগুলো (Entry date, DOB, X-Ray date) সাধারণ টেক্সট বক্স (YYYY-MM-DD), ফোনের নিজস্ব ক্যালেন্ডার পিকার না। ব্যাকএন্ড এমনিতেই এগুলো স্ট্রিং হিসেবে রাখে, তাই কাজ করতে সমস্যা নেই।
- Height ফিল্ড ওয়েবের মতো ড্রপডাউন+টেক্সট দুটো না, শুধু টেক্সট (যেমন "05 Feet 06 Inch")।
- Admin Report analytics (চার্ট, CSV/Word/PDF export) এখনো যোগ হয়নি, Reports hub-এ "ওয়েব থেকে দেখুন" নোট আছে।

**Notification নিয়ে সৎ কথা:** doc-এ যেটা "FCM পাঠানো" বলা ছিল, সেটা আসল push notification — ফোন বন্ধ থাকলেও ঘণ্টি বাজে। সেটা বানাতে BEST-এর নিজস্ব **Firebase প্রজেক্ট** লাগবে (Google অ্যাকাউন্ট, `google-services.json`, service account key EAS-এ আপলোড), যেটা আমার কাছে নেই। তাই এখন যা আছে সেটা হলো **অ্যাপ খোলা অবস্থায়** Callback রিকোয়েস্ট দেখা ও সামলানোর স্ক্রিন — কাজের, কিন্তু ফোন বন্ধ/ব্যাকগ্রাউন্ডে থাকলে জানাবে না। আসল push notification পরে যোগ করা যাবে, Firebase প্রজেক্ট রেডি হলে।

**নিরাপত্তা নিয়ে সৎ কথা:** স্ক্রিনশট-বন্ধ (`expo-screen-capture`) ব্রাউজারে কাজ করে না (এমনকি চেষ্টা করলে পুরো অ্যাপ ক্র্যাশ করছিল, সেটা ঠিক করা হয়েছে — এখন ব্রাউজারে চুপচাপ স্কিপ করে)। আসল Android/iOS ফোনে এটা কাজ করার কথা, কিন্তু যেহেতু এখনো কোনো ফোনে অ্যাপ ইনস্টল করে চালানো হয়নি (EAS build ছাড়া সম্ভব না), তাই সত্যিই স্ক্রিনশট আটকায় কিনা সেটা এখনো চোখে দেখে যাচাই করা যায়নি।

## EAS Android Build — সম্পন্ন ✅

প্রজেক্ট **@nexoviait/best-diagnostic** ([expo.dev](https://expo.dev/accounts/nexoviait/projects/best-diagnostic)) তৈরি হয়েছে, আর প্রথম Android preview build (APK) সফলভাবে সম্পন্ন হয়েছে।

**APK ডাউনলোড:** https://expo.dev/artifacts/eas/J-tVXZ3fGq9Tyhs7qIToJW3UDGkVbq96wLB19b42kQs.apk

একটা গুরুত্বপূর্ণ কারিগরি সমস্যা হয়েছিল এবং ঠিক করা হয়েছে: `best_mobile_app` ফোল্ডারের নিজস্ব `.git` না থাকায় EAS পুরো Laravel প্রজেক্ট (৩.৩ GB, ২ GB সীমার বেশি) আপলোড করার চেষ্টা করছিল। `best_mobile_app`-কে আলাদা, স্বনির্ভর git repo বানানোর পর (node_modules বাদে, ১২৭টা ফাইল) আর্কাইভ ২.৫ MB-এ নেমে আসে এবং বিল্ড স্বাভাবিকভাবে সম্পন্ন হয়। এই আলাদা repo মূল Laravel repo-কে প্রভাবিত করে না।

**পরের বার নতুন বিল্ড লাগলে** (কোড আপডেটের পর): `best_mobile_app`-এ `git add -A && git commit` করে তারপর `EXPO_TOKEN=<token> npx eas-cli build -p android --profile preview --non-interactive --no-wait` চালালেই হবে। Play Store-এর জন্য চূড়ান্ত `.aab` বানাতে `--profile production` ব্যবহার করতে হবে।

**মনে রাখবেন:** APK লাইভ সার্ভারে (`admin.bestdiagnostic.com.bd`) কানেক্ট করে, তাই পুরোপুরি কাজ করতে ব্যাকএন্ডের নতুন কোড VPS-এ ডেপ্লয় করা থাকতে হবে (`docs/mobile-api.md`)।

## Play Store চেকলিস্ট

প্রথম দুটো কাজ (অ্যাকাউন্ট ও প্রাইভেসি পলিসি) আলাদা করে এখনই শুরু করা যায়, কারণ ওগুলোতেই সবচেয়ে বেশি সময় লাগে।

- [ ] Google Play Developer অ্যাকাউন্ট (একবারের ২৫ ডলার) খোলা ও পরিচয় যাচাই সম্পন্ন করা
- [ ] পার্সোনাল নাকি অর্গানাইজেশন অ্যাকাউন্ট, তা ঠিক করা। পার্সোনাল হলে প্রোডাকশনের আগে সাধারণত ১২ জন টেস্টারের সঙ্গে ১৪ দিনের closed testing লাগে (নিয়ম বদলাতে পারে, Play Console-এ শেষ বার দেখে নিন)
- [ ] Package name ঠিক করা, যেমন `bd.com.bestdiagnostic.app`। এটা পরে আর বদলানো যাবে না
- [ ] প্রাইভেসি পলিসি পেজ ওয়েবসাইটে প্রকাশ (পাসপোর্ট, স্বাস্থ্য তথ্য, ছবি, ফোন নম্বর কী নেওয়া হয়, কেন, কতদিন রাখা হয়, মুছতে কীভাবে জানানো যায়)
- [ ] Data Safety ফর্ম ও Health apps declaration পূরণ
- [ ] **ডেমো স্টাফ অ্যাকাউন্ট:** "App access" এ রিভিউয়ারকে লগইন দিতে হবে। এতে আসল রোগীর ডাটা থাকা চলবে না, তাই নমুনা ডাটা সহ আলাদা একটা অ্যাকাউন্ট বানাতে হবে
- [ ] অ্যাপ আইকন (512×512), Feature graphic (1024×500), কমপক্ষে ২টা ফোন স্ক্রিনশট, ছোট ও পূর্ণ বিবরণ
- [ ] Content rating ও Target audience প্রশ্নাবলী
- [ ] `.aab` বিল্ড (`eas build -p android`), Play App Signing চালু, upload key ব্যাকআপ
- [ ] Internal testing → Closed testing → Production

সবচেয়ে বড় তারিখ হিসাব: অ্যাকাউন্ট তৈরি থেকে Production-এ পৌঁছাতে পার্সোনাল অ্যাকাউন্টে কমপক্ষে ২-৩ সপ্তাহ ধরে নিন।
